# 0013 — Internationalisation

**Status:** Accepted (revised after review)

## Decision
- Ship **English, Spanish and French** from day one: user app, staff app, emails, push.
- ICU MessageFormat catalogs per package and app (`packages/i18n`), using keys rather than
  English text. CI fails on missing keys in any shipped locale or unused keys.
- **Locale resolution**:
  - members: member preference, then the board default
  - guests: the `bp` cookie, then the board default (ADR 0006)
  - `Accept-Language` only drives a client-side "switch language?" suggestion, so cached guest
    pages stay deterministic
- Templates use `{% t "key" vars %}`; React uses `useT()`. Dates and numbers use `Intl`.
- **Runtime catalogs** (themes, plugins, admin overrides) can't be checked by repo CI, so they
  are validated **at install/save time**: ICU syntax must parse, placeholders must match the
  base key, and missing keys fall back to `en` with a completeness report in the staff app.
- Admin overrides are stored in the DB and cached under tag `i18n:{locale}`.
- URLs are not localised. Slugs come from content (transliterated).
- Seed data includes es and fr content and members.

## Consequences
- No hard-coded user-facing strings anywhere, enforced by lint where possible.
