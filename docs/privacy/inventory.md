# Personal-data inventory

This is the enforced inventory required by [ADR 0012](../adr/0012-privacy-pii-gdpr.md). Every
column that holds personal data carries a `@personal class=<class>` database comment. The
checker (`bun run privacy:check`, part of `bun run check`) compares those comments with the
database table below and fails if a tagged column is unlisted, if a listed column has no tag,
or if the class differs.

**Classes**

- **restricted** — reachable only through audited definer functions in `pii`.
- **personal-content** — member-created content and profile data, governed by normal `can()` rules.
- **security-record** — bans, warnings, moderation and audit records retained on a documented basis.
- **derived** — caches, counters, search vectors and identifiers-only bookkeeping.

## Storage and other locations

These locations hold personal data outside the relational columns above. They are listed so
erasure, export and retention cover them too; they are not part of the column-tag checker.

| Location | Class | Purpose | Retention | Erasure |
|---|---|---|---|---|
| Object storage `avatars/` | personal-content | Uploaded member avatars | Until replaced or erased | Deleted by the erasure job |
| Object storage `attachments/` | personal-content | Uploaded member attachments | Until the post/attachment is deleted | Deleted by the erasure job |
| Object storage `exports/<uuid>.zip` | personal-content | Export archive handed to the member | 7 days | Deleted on expiry |
| Object storage `journal/<date>/<seq>.json` | security-record | Erasure journal (IDs and timestamps only) | 2 years | Kept as proof of erasure; replayed after restore |
| Plugin schemas | personal-content | Data a plugin declares in `core.plugin_personal_data` | Plugin-defined, removed by `gdpr.erase` | Plugin erase hook, or maintenance sandbox |
| Redis/render caches and CDN entries | derived | Rendered fragments and cache metadata | Until invalidated or expired | Invalidated by erasure/re-render |
| `core.events` and `core.event_deliveries` | derived | Transactional outbox; payloads carry IDs only | Until published/expired | Purged by retention |
| Search vectors (`tsv`, `tsv_simple`, `search_vector`, `title_search_vector`) | derived | Materialised search indexes | Until re-rendered/purged | Rebuilt or deleted with the source row |
| Email in flight (SMTP mock/queue) and `core.digest_deliveries` | derived | Delivery address resolved at send time from `pii` | Transient | Delivery refused for erasing members; the address is never stored outside `pii` |
| Backups | personal-content | Database and object snapshots | 35-day rolling window | Erasure propagates as backups expire; documented in the privacy policy |

## Backups and retention

Backups retain erased data for up to 35 days; erasures, session/API-key revocations and
push-device deletions are appended to the erasure journal outside the database rollback set
(ADR 0012, ADR 0020).
